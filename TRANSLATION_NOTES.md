### Arabic (ar)

Translated from the frozen English snapshot `en-snapshot-p1.json` (1,507 messages); keys added since then were
translated in later passes.

#### Register and variety
- Modern Standard Arabic for the UAE and Saudi Arabia, kept plain and short.
- The user is addressed in the **masculine singular** (اختر، أضف، أنت), the usual default for Gulf consumer
  apps. If gender-neutral wording is wanted later, the imperatives would need a rewrite (e.g. plural forms or
  noun phrases like «إضافة»).
- Digits are left as Western digits (0–9) as in the English, matching common UAE/Saudi web usage. Currency
  codes, brand names (Netflix, Google Ads Settings, AdSense, iCloud, Google One, Claude, Safari, iPhone/iPad,
  Visa), "50/30/20", URLs and e-mail addresses are unchanged.
- Arrows in click paths (“Start over → Delete everything”) are written as `←` because the page reads right to
  left (privacy.sections.summary.item3_html, privacy.sections.device.p2_html, contact.faq.delete.a_html).

#### Decisions worth reviewing
- **Product name**: "Household Budget Optimizer & Savings Simulator" → «مُحسِّن ميزانية الأسرة ومحاكي الادخار»;
  short brand "Budget Optimizer" → «مُحسِّن الميزانية». If the brand should stay in English, change
  `layout.brand`, `page.header.brand`, `page.hero.title_html`, `seo.*`, `contact.mail.subject` and `*.seo.*`.
- **Plurals**: all six categories are filled. `one` and `two` use the Arabic singular/dual words without the
  number (e.g. «شهر واحد», «شهران»/«شهرين» by case); `few` uses the plural (3–10), `many` the accusative
  singular (11–99, «شهرًا»), `zero`/`other` the genitive singular. Where English had only `other`
  (e.g. calc.health.tip.*, months.banners.cap) all six were still written.
- **Sentences with a number but no plural object** (e.g. `goals.summary.emergencyFull` "{months} months",
  `charts.yearsValueText` "{years} years", `goals.emergency.cover_html`) use the generic singular
  («{months} شهر», «{years} سنة») because the code doesn't pass a plural count. Grammatical for 11+ and
  acceptable, but «3 شهر» is slightly off; turning these into plural messages would fix it.
- **Day-of-month picker** (`payday.dayOfMonth` + `payday.ordinal.*`): Arabic has no st/nd/rd/th. The
  ordinal values are a single invisible right-to-left mark (U+200F) instead of empty strings, because
  `npm run i18n:check` reports an empty string as "must be a string" (`isPlural("")` returns `""`, not
  `false`). The visible result is «اليوم 5 من الشهر».
- **Sentence fragments joined in code**: `rules.*.evidence` + `format.pctWords.*` + `plan.explain.*` build
  the "How did we get this?" sentence. Arabic was written so the pieces read as one sentence
  ("… يخفّض عادةً نحو الخُمس (20%) من هذا الإنفاق."), but it should be checked on screen.
  `format.pctWords.all` is «المبلغ كله (100%)».
- `common.periodWord.*` is only used inside `page.summary.receiptTitle_html`; the title was rebuilt as
  «حصيلة <span>الشهر</span>» / «حصيلة السنة», so periodWord is «الشهر» / «السنة» (with the article).
- `rules.*.why` "higher than what's typical for {group}" → «أعلى من المعتاد لدى {group}»; `profiles.*.group`
  are written to fit after «لدى» (e.g. «المستأجرين في المدن»).
- `inputs.toast.sampleLoaded`, `dashboard.categories.basisIncome*`, `page.banners.sample_html` insert the
  profile name after «لملف:» to avoid gender/article agreement with the profile name.
- `historyEngine.alerts.*Singular/*Plural`: Arabic uses the same «{label}: في ارتفاع …» pattern for both,
  avoiding verb agreement with the label.
- Festival lists keep «العيد» first in the Arabic (English order kept for `festivalsDiwali` by putting
  ديوالي first). «الكريسماس» used for Christmas; «عيد الميلاد المجيد» is a more formal alternative.
- `help.text.giving` mentions zakat, tithes and church/temple offerings as in the English.
- The money-tips article (`page.guide.*`) keeps the US figures from the English ($, °F with °C), as
  instructed (numbers unchanged). It reads a little foreign for Gulf readers; consider localised examples.

#### Phrases worth a second look
- `rules.*.evidence`: these are sentence starts that get "{words}" and "dieser Ausgaben/Zinsen" added after them
  (`plan.explain.evidence*`). Each one ends in "spart meist" / "vermeidet meist" so the sentence works, e.g.
  "Wer jedes Jahr Angebote vergleicht, spart meist etwa ein Viertel (25 %) dieser Ausgaben." Please check a few in the app.
- `rules.*.noun` goes into "…gibst du {amount} im Monat für {noun} aus", so nouns are in the accusative
  (e.g. `carRefinance.noun` = "die Rate für deinen Autokredit").
- `profiles.*.group` goes into "üblich für {group}": "Stadtmieter", "Familien", "junge Berufstätige".
  "Stadtmieter" is the generic masculine; a gender-neutral alternative would be "Mietende in der Stadt".
- `historyEngine.alerts.*Singular/*Plural`: English changes the verb by label number. German uses one neutral
  pattern for both ("{label}: 3 Monate in Folge gestiegen."), so Singular and Plural are the same text.
- `dashboard.summary.easyTips`: written in the accusative ("1 einfachen Tipp" / "3 einfache Tipps"), because it only
  appears inside "Wenn du {tips} befolgst, …".
- `plan.costPayback`: "Kostet einmalig {amount}, hat sich bezahlt gemacht nach: {time}." The colon avoids a case
  clash with `format.duration` ("3 Monate" vs "nach 3 Monaten"). Same idea in `goals.status.progress`
  ("Dauer: {time}") and `goals.summary.emergencyIn` ("3 Monate: noch etwa {time}").
- `payday.dayOfMonth` / `payday.ordinal.*`: every ordinal suffix is "." → "15. des Monats". `payday.lastDay` =

- `months.goals.savedIn`: "Gespeichert in {month}" assumes {month} is "Oktober 2026"; "im Oktober 2026" would

#### Legal text: needs professional review
`privacy.*`, `terms.*` and `layout.footer.disclaimer.*` are faithful plain-language translations, **not legally
reviewed**. A German lawyer should check them before launch, in particular:
- whether "du" is acceptable in the legal pages, or whether "Sie" is preferred there;

- German sites usually also need an Impressum, which the English source doesn't have.

#### Decisions worth reviewing
- **Product name**: "Household Budget Optimizer & Savings Simulator" is translated as
  "Optimizador de presupuesto familiar y simulador de ahorro"; the short brand "Budget Optimizer" as
  "Optimizador de Presupuesto". If the brand should stay in English, change `layout.brand`, `page.header.brand`,
  `page.hero.title_html`, `seo.*`, `contact.mail.subject` and the `*.seo.*` titles.
- **Day-of-month picker** (`payday.dayOfMonth` + `payday.ordinal.*`): Spanish doesn't use st/nd/rd/th. Empty
  suffixes fail `i18n:check` (it treats "" as not-a-string), so the suffix carries the rest of the phrase:
  `dayOfMonth` = "Día {day}{suffix}", each ordinal = " de cada mes" → "Día 5 de cada mes". `page.payday.dayLabel`
  became "Día de cobro" so the label + option read naturally. If the code ever uses the ordinal keys elsewhere,
  revisit this.
- **Plurals**: Spanish categories are one, many, other. `many` (used by Intl for numbers like 1,000,000) uses
  "{count} de meses" etc. English messages with only `other` (e.g. `calc.health.tip.*`, `backup.openDialog.overflow`,
  `months.banners.cap`, `months.bars.fit`, `months.stats.sinceCurrencies`) got all three forms. The `one` form
  of `backup.openDialog.overflow` and `months.bars.fit` is written without `{count}`/`{shown}` ("el mes más reciente",
  "el último mes de {count}"). The placeholder union per key is unchanged.
- **Evidence fragments** (`rules.*.evidence*`) are sentence starts that the code completes with
  `format.pctWords.*` and "de este gasto" (`plan.explain.evidenceOfThis`), e.g. "Comparar precios cada año suele
  reducir" + "aproximadamente una décima parte (10%)" + "de este gasto." Check a few in the running app.
- **historyEngine.alerts.\*Singular / \*Plural**: the code picks singular/plural from the English label, but
  Spanish labels have their own number ("Suscripciones", "Agua y gas"). I used "{label}: ha subido…" /
  "{label}: han subido…" with a colon so agreement is less jarring, but some combinations may still read
  slightly off (e.g. "Supermercado: han subido" if English treats "Groceries" as plural). Ideally the code would
  pick the form from a per-language flag.
- **rules.*.why**: "superan lo habitual para {group}" vs "supera" was matched to each Spanish noun; the
  `{group}` values are written to fit "para …" ("quienes viven de alquiler en la ciudad", "familias",
  "jóvenes profesionales").
- **dashboard.categories.basisIncome**: "a typical {profile}" became "lo típico para el perfil «{profile}»"
  because the profile names don't fit after an article.
- **Percent spacing**: kept "{pct}%" without a space (RAE prefers "15 %"), to match the app's number formatting.
- **Numbers in the money-tips article and glossary** (`page.guide.*`, `page.glossary.apr`, `lakhCrore`) keep the
  English figures and separators as written ("$3,000", "100,000", "$46,000"). Mexico reads these naturally;
  Spain would write "3.000 $" / "100.000". °F/°C order was swapped to put Celsius first (values unchanged).
- **charts.on / off** are a state label for the inflation toggle: "Activado" / "Desactivado".
- "Nice-to-haves" is translated as "caprichos" throughout (needs = "facturas obligatorias").
- "Health score" = "puntuación de salud"; "Payday" = "día de cobro"; "Backup" = "copia de seguridad".

### French (fr)

#### General choices
- Market: France. Polite **vous** throughout, plain everyday words.
- Typography: non-breaking space (U+00A0) before `:` `;` `?` `!` `%` and `°`, inside `« »`, and as the
  thousands separator in numbers written in the text ("3 000 $"). Apostrophes are typographic (’).
- Plurals use the French categories `one`, `many`, `other` (`many` is for 1 000 000-style numbers;
  it uses the same wording as `other`). English messages that only had `other` got all three categories.
- `months.*`: French does not inflect "mois", so most month plurals look the same in each category.

#### Terms and possible alternatives
- Emergency fund = « épargne de précaution » (alternative: « fonds d'urgence », used more in Canada).
- APR = « TAEG » (the legal French term; strictly it includes fees, so it is close to but not exactly APR).
- Take-home pay = « salaire net » (meaning after tax; in France "net" is often understood as *before*
  income tax since the 2019 withholding. « net après impôts » might be clearer).
- Health score = « note santé ». Nice-to-haves = « petits plaisirs ». Must-pay bills = « dépenses obligatoires ».
- Mortgage = « crédit immobilier ». "Mortgage insurance" (rules.rentBurden.tips.ownerInsurance) was
  translated literally as « assurance de prêt hypothécaire »; in France the usual product is
  « assurance emprunteur », which does not stop at 20 % equity. The tip is US-centric; needs review.
- Property tax appeal (rules.rentBurden.*) = « contester sa taxe foncière ». Also US-centric.
- Toll tag = « badge de télépéage ». Store brands = « marques distributeur ».
- "Committee payment" (help.text.other) = « tontine ».
- Brand: `page.header.brand` / `layout.brand` kept as "Budget Optimizer" (product name). The long
  title is translated as « Optimiseur de budget familial et simulateur d'épargne ».
- Profiles: « Célibataire locataire en ville », « Famille de 4 en périphérie », « Jeune actif ».
  Profile `group` values include the article (« les familles ») because they follow « pour ».

#### Sentence assembly (please review in context)
- `rules.*.evidence` strings end with « permet généralement d'économiser » (or « d'éviter » for debt) so
  that `plan.explain.evidence` / `evidenceOfThis` read « … permet généralement d'économiser environ un
  quart (25 %) de cette dépense. ».
- `rules.*.noun` values include the article (« vos assurances habitation et auto », « l'électricité et
  le gaz ») because they follow « … par mois pour {noun} ».
- `historyEngine.alerts.*`: rewritten as « {label} : en hausse depuis {count} mois d'affilée. » to avoid
  gender/number agreement with the label. Singular and plural variants are the same.
- Toasts that started with `{month}` were rephrased (« Mois enregistré : {month} ») because month names
  are lowercase in French.
- `payday.dayOfMonth` / `payday.ordinal.*`: French ordinals can't be done with the English st/nd/rd/th
  split (1 → « 1er », 21 → « 21 »). Used `"Le {day} {suffix}"` with every ordinal = « du mois », so the
  options read « Le 1 du mois », « Le 21 du mois ». « Le 1 » (instead of « Le 1er ») is slightly off;
  will be fixed when these keys move to locale ordinals. `page.payday.dayLabel` became « Ma paie arrive : »
  so it does not repeat « le ».
- `charts.returns.*.label`: the live en.json now has `{pct}%:` in these labels (changed after the
  snapshot), so the French uses `{pct} % : …` to match the current source and keep `i18n:check` clean.

#### Sentences built from pieces (please review in the running app)

  last, so each `evidence` fragment is written as "X करने से आमतौर पर" ("by doing X, usually") and
  the templates finish the sentence: "{evidence} इस खर्च का {words} बच जाता है।". Result, e.g.:
  "ख़रीदने से पहले 24 घंटे रुकने से आमतौर पर इस खर्च का लगभग पाँचवाँ हिस्सा (20%) बच जाता है।"

- **`rules.*.noun`** is used after "पर" in `plan.explain.start` ("हर महीने {noun} पर {amount} खर्च"),
  so nouns are in the oblique form (e.g. "किराए या होम लोन", "डॉक्टर और दवाइयों").
- **`profiles.*.group`** is always followed by "के लिए/के", so groups are oblique plural

- **`dashboard.summary.tips` / `easyTips`** ("other" form "सुझावों") are inserted into
  "{tips} पर चलकर…", which needs the oblique plural.
- **`plan.costPayback`** reads "…लागत वसूल होने का समय: {time}।" so that `format.duration.now`

#### Grammar built around sentence fragments
- `rules.*.evidence*` are sentence starts that `plan.explain.*` completes. English puts the verb first ("…usually cuts {words}"), but Urdu puts it last. So each Urdu `evidence` ends with "…سے عموماً" ("by doing X, usually"), and `plan.explain.evidence` / `evidenceOfThis` / `interest*` add the verb after `{words}` ("…بچ جاتا ہے"). **If anyone edits one side, check the other side still fits.**
- `profiles.*.group` is in the oblique plural (e.g. "شہر کے کرایہ داروں") because it is always followed by "کے" ("{group} کے عام خرچ"، "{group} کے لیے").
- `payday.dayOfMonth` is "مہینے کی {day}{suffix}". Every `payday.ordinal.*` is " تاریخ", so the result reads "مہینے کی 5 تاریخ". Urdu has no st/nd/rd/th suffixes.
- `historyEngine.alerts.*` is phrased as "{label} میں … اضافہ/کمی", so it works for any label regardless of gender or number. The Singular and Plural variants are therefore identical.
- `page.banners.sample_html` and `dashboard.categories.basisIncome` insert the profile name as it is (direct case, e.g. "…گھرانہ کے لیے"). A purist would use the oblique form ("گھرانے"), but that can't be done with a placeholder. It's acceptable but slightly unnatural.
- `inputs.housing.no` and `inputs.subs.rarely` use "دیتا/دیتی" and "کرتا/کرتی" to cover both genders, because first-person verbs in Urdu are gendered.
- `dashboard.split.ofIncome_html`: the tag order is fixed (`{pct}` first, then the text), so it reads "{pct} آمدنی کا". This is understandable but terse.
- `page.growth.extra_html`: the text now comes after the `<span id="fvYears">` (the span itself is unchanged) so the Urdu word order works.
